# 12. Windows MSIX Packaging and Microsoft Store Distribution

Date: 2026-09-19

## Status

Accepted

## Context

On Windows, Atlas distributes standalone portable executables (`Atlas-x86_64-Portable.exe`) and traditional Inno Setup installers (`installer/Atlas.iss`). While effective for direct GitHub downloads, broad distribution via the Microsoft Store offers automated background updates, trusted installation without browser security warnings, and elevated discovery.

Microsoft Store distribution requires modern `.msix` application packaging (Desktop Bridge) and strict adherence to Microsoft Store Policies, specifically:
- **Policy 10.1 (Distinct Value & Quality):** Clear, crash-free execution with responsive UI.
- **Policy 10.2 (Security):** Packaged binaries must not execute stealth operations, malware-like behavioral patterns, or unsigned background processes.
- **Policy 10.5 (Personal Information):** Any app reading user-profile data (such as browser folders) must provide a public Privacy Policy and strictly limit usage to local storage.

## Decision

We establish an official MSIX packaging and Store compliance pipeline:

1. **Desktop Bridge Architecture**:
   - Reuse the exact PyInstaller onedir/onefile payload generated by `main.spec` as the executable core inside an MSIX container.
   - Declare the standard `rescap:runFullTrust` restricted capability in `installer/msix/AppxManifest.xml` to allow standard Win32 execution and access to `%LOCALAPPDATA%` and `%APPDATA%`.
2. **Policy 10.5 (Privacy) Compliance**:
   - Maintain [`PRIVACY.md`](../../PRIVACY.md) at the repository root and link it in the Store listing.
   - Enforce an offline-first architecture with the build-time `enforce_offline_payload` guard, which physically strips network libraries (`socket`, `ssl`, `http`, `QtNetwork`) from the binary payload.
3. **Reviewer & Certification Documentation**:
   - Provide pre-written "Notes for Certification" in `installer/msix/README.md` explaining the read-only browser scanning, absence of network telemetry, and lack of DPAPI credential decryption.
4. **Isolated Metadata**:
   - Store MSIX manifest templates and Store packaging guides under `installer/msix/`, keeping packaging metadata cleanly segregated from application source code.

## Consequences

- Windows users can install Atlas directly from the Microsoft Store with automatic updates.
- Store certification testers have an exact guide and clear architectural rationale for all declared capabilities.
- Atlas maintains complete privacy compliance without modifying core application code.
